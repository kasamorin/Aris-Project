## 3. 施工纪律（四条铁律 + 一条流程）

1. **顺序不可倒**：地基 → 组装根 → 角色 → 会话落库 → skills → 记忆数据层 → 聚类/compact →
   记忆语义 → WebUI → 发布。两个"为什么排这里"的硬理由见 M0 / M1 开头。
2. **`provide` 只许发生在 `serve.assemble()`**：`skills.menu` 现在是会话构造时注册的全局
   单槽（`src/aris/behavior/skills/manager.py:59` ← `src/aris/chat/session.py:135`），
   单进程多会话下**后开的会话会覆盖前面的**。M1 必须先修掉。
3. **`system prompt` 全程静态、可变量只从尾部进**：角色提示 + 工具提示 + skills 菜单在构造期
   拼一次（`src/aris/chat/session.py:136-142`）；记忆块拼在历史尾部、**不入库、不回灌**。
4. **迁移只加不改名**：`src/aris/store/migrate.py:118` 的 drift 检查对已应用迁移**改名即报错**；
   owner = `memory` 的版本号与名字一次定死。
5. **流程**：每阶段 feature 分支 → 小粒度提交 → `--no-ff` 合回 develop → 删分支；
   daily 不碰 main（main 只在发版时进）。

### M0 可迁移性与启动幂等（D14）

**为什么最先**：PG 角色名必须在**建任何新表之前**定死。否则 memory 三表建在 `$USER` 名下，

    重获取；**角色探测对齐**（已有 `pgdata` 就按它实际的角色名连，**新建实例才 `initdb -U aris`**

  - `aris doctor`：加「迁移自检」——`data/` 分层完整性 + PG 可运行性

- **验证**：拷 `data/` 到临时目录跑；占住 55432 端口跑一次；换角色名场景跑一次
- **风险**：旧 `pgdata` 属主不同**不能自动修** → 报可操作错误（写清 `chown` 或重建）
- **✅ 已完成（2026-10-01）**：`store/pgenv.py` 新增 `probe_runnable` / `choose_port` /
  `align_user` / `legacy_role_hints` / `ownership_error` / `socket_port` / 角色标记读写；
  `store/bootstrap.py` 新增 `_clear_stale_runtime`（pidfile + socket 锁文件）；`datadir.py`（v0.4.4 后并入 `paths.py`）

  实测：拷 `data/` 到别处可起、55432 被占自动改 34557（**另一进程也能反推**）、

### M5 记忆数据层（D16 §七）

1. `memory/conf.py` + `config/memory.toml` —— **扁平键**（`cfgtoml` 不支持嵌套表，`cfgtoml.py:29`）：
   `halflife_tier2=14` / `halflife_tier3=180` / `weight_init=100` / `hit_gain=100` /
   `threshold_key=500` / `cap=800` / `threshold_vanish=5` / 注入条数与字数 / `recent_days=14` /
   `fallback_hours=12`
2. `memory/migrations.py` 建 `memory_entries`（含 `pinned_at` / `visibility` 两列）+
   复合索引 `(cid, tier, kind, occurred_from DESC)` + 活跃索引；**HNSW 先不建**（先导数据后建索引）
3. 给 `store.vector.ensure_index`（`store/vector.py:98`）**加 `where` 参数**（现在没有）→
   建 partial HNSW `WHERE embedding IS NOT NULL`
4. `memory/service.py` 最小闭环：写一条 event → 取候选 → 算 `w_eff` 重排 → 写回命中

- **两条硬约束（勘察实测）**
  - **`w_eff` 不能进 SQL 的 ORDER BY / 表达式索引**（含 `now()`，stable 非 immutable → 退化成
    顺序扫描）→ 两段式：SQL 用等值/范围列压候选，向量路取 ANN `top-k × 3~5`，Python 里算
    `w_eff` 重排
  - **命中写回必须独立事务**：`store.vector.search` 自建连接、用完即关且**未提交**
    （`store/__init__.py:91`），混进 UPDATE 会连带回滚并搅乱 `SET LOCAL hnsw.ef_search` →
    检索完用另一连接批量 `UPDATE ... WHERE entry_id = ANY(...)`，Python 侧去重，失败只记日志
- **其他坑**：`search` 的 `select` 默认 `*`（`vector.py:213`）→ **必须显式列**；
  `upsert` 冲突键默认 `id`（`vector.py:139`）→ 传 `conflict_key="entry_id"`；
  `kind` 分流一律显式条件（**不能拿 `embedding IS NOT NULL` 反推**），建议 CHECK 或 StrEnum
- **验证**：`aris db migrate` 后 `\d memory_entries`；衰减公式单测；命中去重幂等；
  测试显式传 `migrations=` 隔离

### M6 聚类 + compact（D3/D4/D5 + D16 §六）

- **聚类**：`memory/grouping.py` 纯函数（k=2 的 1D k-means ⇒ 取最大间隔切分 + 递归 + 停止条件
  「子段最大间隔 / 中位间隔 ≥ 3~5」）；物化进 `memory_conversations`，**重算幂等**、
  增量 + `recomputed_at`；**不引调度器**
- **compact**：插入点 `src/aris/chat/session.py:214` 组装 `list(self.history)` 处
  （loop/engine/formatters 无状态、不该承担）；触发 = 字符估算 token × `context_length` 比例
  ⚠️ **`context_length` 目前不参与任何决策**（只在展示链路），要先从 `LLMProvider.get_model` 接线；
  同 `session_id` 旧消息打 `archived_at` + 写 `kind=compact` 摘要；
  重组 = `system + 记忆块 +〔摘要 + 前 3 条原文〕`；摘要失败 → 不压缩继续（记日志）
- **验证**：聚类单测（等间隔/单条/巨间隔/跨天）；`tests/support/mock_llm_server.py` 脚本化摘要，

## 6. 记忆模块最终形态（重点）

**一句话**：会话与消息落库 → 每段连续对话结束提炼「总结 + 事件」→ 每两周聚成「两周记」→
权重随时间惰性衰减、被用到才涨 → 对话时把「关键记忆 + 近期事件 + 最近两周记」拼在历史尾部 →
平时靠 Aris 自己 `memory_search`，12 小时没搜过就兜底替它搜一次 → 全部能在 `/memory` 页看和改。

### 6.1 一轮对话的完整数据流

```
用户消息 ──append──> memory_messages（cid / session_id / seq）
    │
    ├─ 组装请求（每轮一次查询取三块，不缓存）
    │    system（静态：角色提示 + 工具提示 + skills 菜单）
    │  + [关键记忆 ≤7 | 近 14 天事件 ≤10 | 最近两周记 1 篇]   ← 末条 user 之前
    │  + 历史（archived_at IS NULL 的尾部）
    │  + 末条 user〔+ 12h 兜底检索结果〕                      ← 兜底才在之后
    │
    ├─ agent loop（工具轮细节不入库）
    ├─ 回复 ──append──> memory_messages
    │
    ├─ 超阈值 ─> compact：旧消息打 archived_at，摘要落 memory_entries(kind=compact)
    ├─ 大会话边界 ─> 一次调用产 总结(kind=summary) + N 个事件(kind=event)
    │                 事件 embed → 唯一进向量库的产物
    ├─ 每两周 ─> 两周记(kind=digest)：吃该窗口 summary + compact，不向量化
    └─ 检索命中 ─> hit_count+1、last_reinforced_at=now（独立事务、一次调用内去重）
```

### 6.2 权重与衰减（整数，无浮点）

```
w_eff = (weight + hit_count × 100) >> floor(Δt / H)，Δ = now − last_reinforced_at
```

初始 `weight=100`｜命中 `+100`｜关键阈值 `500`（直接进上下文）｜封顶 `800`｜消失 `<5`（不注入不检索）
｜负数 = 软隐藏｜H：二级 14 天 / 三级 180 天。
**读时惰性计算、不落库**（无 autorun 也能跑）；**衰减 = 每过一个半衰期整体右移一位**；
想更平滑就调小 `H`。1 点 = 旧浮点方案的 0.01，够手动微调。

### 6.3 四张表

`memory_sessions` / `memory_messages` / `memory_conversations`（M3）+ `memory_entries`（M5，二三级同表，
`tier`+`kind` 区分，`embedding` 可空、**只有事件有**）。字段全表见 `MEMORY.md` 第七节。

### 6.4 总线服务面

`memory.session_current` / `memory.history_load` / `memory.message_append` / `memory.archive` /
`memory.compact` / `memory.inject_context` / `memory.search` / `memory.entries.list|set_weight|hide|purge` /
`memory.digest` / `memory.conversations_rebuild` / `memory.conversations_list` / `memory.stats` /
`memory.start`；`character.list`（`character.system_prompt` 加必填 `cid`）。

### 6.5 CLI（无 GUI 与调试用）

`aris memory list|set-weight|hide|pin|visibility|purge|stats|recompute|rebuild-index`。

### 6.6 调用成本

普通一轮 **1 次 LLM 调用**；compact 偶发 +1；大会话结束 +1（产总结 + 全部事件）；每两周 +1；
12h 兜底检索只走本地 embedding，**不调 LLM**。

### 6.7 明确不做（v1.0 边界）

冷库（1024 维）、历史消息检索工具 recall、GraphRAG、视觉/多模态、autorun、知识库第二阶段
（PDF/混合检索）、Responses API、提供商降级纪律、rc 通道、人格分裂。

## 7. 版本与发布（beta / 正式两渠道，都发布在 main）

| 渠道 | tag | `__version__` | 发布分支 |
|---|---|---|---|
| beta（小版本更新） | `beta-vX.Y.Z` | `X.Y.Z` | `main` |
| 正式版 | `vX.Y.Z` | `X.Y.Z` | `main` |

- **版本串只写数字**：`X.Y.Z` / `X.Y.Z.W`，不带 `.dev0` / `-beta` 等后缀；渠道只由 tag 表达
- **号码全线唯一**：beta 与正式共用一条数字线，同一个号只能出现一次；
  有 `beta-v1.0.1` 就没有 `v1.0.1`，反之亦然；要发另一个渠道就用更高的号
- beta 不是预发布，只是小版本更新标记
- **密集小版本**可下探一段：`vX.Y.Z.W`（beta 线写 `beta-vX.Y.Z.W`）
- 用法：`bash scripts/bump-version.sh <版本|patch|minor|major>`；规则实现在 `scripts/lib-version.sh`，
  `release-check.sh` 共用
- v1.0 期间：beta 用 `0.9.x`（如 `0.9.0`、`0.9.1`），`1.0.0` 留给正式版；
  全部完成 → `bump-version.sh 1.0.0` → 合 main → tag `v1.0.0`
- **alpha 渠道（后续）**：只在 `develop` 发布，用于 v1.0.0 预发布；tag 形态与号码规则届时再定，当前不实现
- 旧规则作废：`.dev0`、`vX.Y.ZbN` 候选线、`v0.4.2-beta`（后缀式）、"0.x 全段为 beta"；历史 tag 不动
