## 2. W1 变更记录迁移（核心）

### 2.1 目标结构

```
CHANGELOG.md          # [Unreleased] + 当前最新版本（永远只有这两段）
changelogs/
  README.md           # 归档说明与索引
  <版本>.md           # 历史版本，一个版本一个文件（发版时由上一版本移入）
```

规则：

- `CHANGELOG.md` 顶部固定 `## [Unreleased]`，分类：`新增 / 改进 / 修复 / 升级注意`；
- 版本段标题：`## [0.4.5] - YYYY-MM-DD`；
- 版本开头可有 `### 亮点`（**不强制**），人话写 2~3 条；
- 不兼容项放 `升级注意`，写清迁移方式；
- 每次发版：新版本段写进 `CHANGELOG.md`，**上一版本整段移入 `changelogs/<版本>.md`**；
- 归档缩略：`CHANGELOG.md` 超过约 2000 行或满一年时，把最旧版本移入归档（自动化留 v1）。

### 2.2 内容迁移

## 4. W3 发版流程与脚本

### 4.1 定稿流程

日常：

```
feature 分支 → PR → develop（--no-ff 合并）
```

发版（**只有一次 PR**）：

1. 从最新 `develop` 切 `release/v0.4.5`；
2. 在该分支：`bash scripts/bump-version.sh 0.4.5` + 封 `CHANGELOG.md`；
3. `bash scripts/release-check.sh` 必须 PASS；
4. 提交 `chore(release): v0.4.5 …`；
5. 推送 release 分支到 fork；
6. 上游 PR：`release/v0.4.5 → main`（首次合并会带出此前差异）；
7. 合并后在上游 `main` 打 tag `v0.4.5` 并推送；
8. 再开 PR：`main → develop`，标题 `chore: 同步 main 回 develop`，`--no-ff` 合并；
9. 删除 release 分支（本地与远端）；
10. **不创建 GitHub Release**（等 GUI 打包后补）。

alpha 例外：只在 develop 打 `alpha-vX.Y.Z`，不进 main。

### 4.2 `scripts/release.sh`

一个本地脚本（**不自动推送**），职责：

- 校验：当前在 develop、工作区干净、与 upstream/develop 同步、版本号未占用；
- 切 `release/vX.Y.Z`（参数给版本或 patch/minor/major）；
- 调 `bump-version.sh`；
- 提示手工封 `CHANGELOG.md`（不自动改内容，避免生成没人味的文字）；
- 跑 `release-check.sh`；
- 打印后续命令：提交、推送、PR 链接、tag 命令、回合并命令。


### 4.3 仓库与 tag

- fork：`kasamorin/Aris-Project`；上游：`aris-project-ai/Aris-Project`；
- 发布 PR 在上游开；tag 打在上游 main 的合并提交上；
- 我的权限边界：**AI 不执行 git push**；所有推送由开发者执行。

### 4.4 附带小项：会话冷却默认值

与本版标准化一起改（**小代码项**，不动功能）：

### 5.1 附带小项：清理文档中的 `docs/archive` 引用（独立小任务，**可交给另一个 agent**）

**背景**：`docs/archive/` 在 `.gitignore` 里——只在本机存在、不随仓库分发。任何文档指向它，
对别人（以及新克隆）就是死链。因此**除 `.gitignore` 与该目录自身，其他文档一律不再出现这个路径**；
**目录本身与里面的文件保持原样，不删、不改、不移**。

**范围**（2026-11-01 全仓 grep 结果，执行时重新 grep 复核，以当时为准）：

| `docs/forAiDoc/PORTABILITY-AND-SINGLE-SESSION.md` | 头部「（`docs/archive/discuss-…` 的补充 D14/D15…）」 | 删除该括号内容，保留「2026-09-28 商讨定案」 |
| `.gitignore` | 注释里的「（见 AGENTS.md §10）」 | 改为不指向 AGENTS（§10 不再提该目录） |

**替换口径**（统一用这些说法，不要改写成「归档到另一个目录」）：

- 「阶段结束后移入 `docs/archive/`」→「阶段结束后从仓库移除，本机留档」；
- 「历史条目在 `docs/archive/…`」→「历史条目不在仓库内」；
- 「已归档到 `docs/archive/…`」→「已从仓库移除」；
- 只是顺带提到「取消跟踪 archive」的历史条目：**直接删掉该短语**（`git log` 能查到，不必留在文档里）；
- 目录地图 / 文档路由里单独指向该目录的行：**整行删除**。

**不动**：

- `docs/archive/` 目录及其中的全部文件（这是本次任务的前提，误删算事故）；
- 文档 / 代码里的 `archived_at` **字段名**（那是数据库字段，不是路径）；
- `.gitignore` 里的 `docs/archive/` 这一行本身（它定义的就是「不跟踪」，是唯一合法出处）；
- `COPYING` 里出现的 archive（GPL 正文，与项目无关）。

**验收**（除 `.gitignore` 与本文件外，应无任何命中）：

```bash
git grep -n 'docs/archive' -- ':!.gitignore' ':!docs/process/v0.4.5.md' || echo 'clean'
```

**注意**：纯文档改动，**不用跑 `check.sh`**；单独提交 `docs: 清理文档中的 docs/archive 引用`，
body 分条列出各文件改了什么；`docs/archive/` 相关文件**一个都不许 stage**（`git status` 复核）。
